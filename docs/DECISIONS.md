> Единственный активный журнал продуктовых решений. Новое решение получает новый ID;
> изменённое решение не переписывает историю, а указывает `Supersedes`.

## Доступ и эксплуатация

### DEC-ACCESS-001 — localhost без пароля

- **Статус:** реализовано 08.09.2026 (`68bdd2c`).
- Панель на `localhost` / `127.0.0.1` открывается без пароля, включая owner/admin функции и WebSocket.
- Обычный запуск слушает только loopback.
- Явный LAN/network bind требует одновременно `PANEL_AUTH_USER`, `PANEL_AUTH_PASS` и
  `TOKEN_ENCRYPTION_KEY`; иначе bind возвращается на `127.0.0.1`.
- Fake QA остаётся отдельным изолированным режимом.

### DEC-OPS-001 — локальный workflow

- Работа ведётся локально маленькими rollback-friendly коммитами.
- Полный pytest, browser, OBS/CEF, production data и реальные provider/ML calls запускаются только
  по отдельному разрешению.
- Для финальной browser/OBS-приёмки владелец должен написать **«поехали»**.

### DEC-OPS-002 — Ollama

- Ollama можно выбрать основным AI provider.
- Image фиксируется exact tag + digest после разрешённого pull и проверки version/startup/health без
  model pull и inference.
- Обновления image только вручную.
- Панель управляет только allowlist-командами Ollama; общий Docker manager не нужен.
- При недоступной Ollama сообщения сохраняются в chat log, но не ждут будущего ответа и не уходят
  автоматически в cloud.
- Панель работает без Docker; приостанавливается только AI, использующий Ollama.
- Модель скачивается только вручную после показа имени, размера и свободного места; pull можно
  отменить с сохранением resumable cache.
- При shutdown панель останавливает контейнер только если сама запустила его в этой process-session.

### DEC-OPS-003 — публикация шагов Hoplite

- **Supersedes:** запрет GitHub/push из старого workflow-текста в `PLAN_TODO.md`.
- Hoplite работает только в текущей ветке, выданной окружением, и не переключается на историческую
  ветку плана.
- Каждый завершённый пункт активного плана после focused tests и `git diff --check` получает
  отдельный commit и сразу публикуется в текущую разрешённую GitHub-ветку.
- Следующий пункт начинается после подтверждения публикации предыдущего; незавершённые или красные
  шаги не публикуются.
- Ограничения `DEC-OPS-001` на full pytest, browser/OBS, production data и реальные provider/ML calls
  сохраняются.

## Scope, widgets и OBS

### DEC-BUS-001 — Widget Bus по каналу

- **Статус:** реализовано 09.09.2026 (`WIDGET-01`).
- Widget Bus разделяется по Twitch-каналам, не по bot account.
- Несколько ботов одного канала публикуют в одну channel-scoped ленту.
- Одно Twitch message/event отображается один раз по стабильному ID.
- Event/data widgets требуют `channel=<login|Twitch ID>`; декоративные widgets могут работать без него.
- Числовой `channel` сначала ищется как точный login, затем как ID.
- Старые data URLs без `channel` fail-closed с локализованной диагностикой.
- Обычный bus доступен только localhost и не требует read token.

### DEC-WIDGET-001 — moderator-media

- **Статус:** реализовано 09.09.2026 (`WIDGET-02`).
- `/widget/moderator-media` — protected per-channel output вне reusable public inventory.
- Token отдельный для канала, ротация только вручную, старый token отключается сразу.
- Новые tokens хранятся plaintext локально вместе с compatibility SHA-256 hash; UI по умолчанию
  показывает маску, reveal/copy доступен только local owner и скрывается через 30 секунд.
- Legacy hash-only URL продолжает работать, но raw token не восстанавливается и честно требует
  явной rotation перед reveal.
- Safe preview не получает рабочий token и не обращается к protected state/file APIs.

### DEC-WIDGET-002 — темы и UI

- Owner panel всегда canonical dark.
- Widget themes меняют только preview/OBS output.
- Обычный content ограничивается примерно 1400–1600 px; таблицы и visual editor могут быть шире.
- Большой frontend split не выполнять без измеренной проблемы производительности.

### DEC-MEDIA-001 — Media Share и YouTube

- **Статус:** реализовано 09.09.2026 (`MEDIA-01`).
- Media Share сохраняется; YouTube IFrame API разрешён.
- При первом использовании показывается one-time предупреждение о внешнем сервисе, сети и embed/autoplay
  ограничениях. Согласие хранится в panel settings и может быть сброшено.
- Нужны честные offline/error/reconnect states.
- Song Request пока остаётся модерируемой очередью без autoplay. Будущий autoplay начинается с
  отдельного исследования provider/player вариантов.

## Боты и роли

### DEC-BOTS-001 — обращения и TTS

- Exact nickname/@mention или Twitch Reply разрешает AI-боту рассмотреть ответ, но не гарантирует его.
- Без обращения обычный бот наблюдает и использует чат как контекст.
- Если человек назвал несколько ботов, они могут генерировать ответы параллельно.
- Боты без TTS пишут только текст; весь channel TTS звучит через одну последовательную audio queue.
- Bot-to-bot replies только при прямом обращении; лимит настраивается у каждого бота, default 4, 0 = запрет.
- Moderator может модерировать и разговаривать без обращения, но подчиняется role settings/cooldown.
- Voice companion отвечает по включённым speech/question/silence triggers.

### DEC-BOTS-002 — lurker и Director

- Lurker — non-AI worker: сам не принимает содержательных решений, но ведёт chat/events и выполняет
  проверенное задание Director.
- Director — обязательная задача подготовки к live-релизу по `DEC-DIRECTOR-010`; прежний optional-приоритет
  отменён, но разрешение на реальные внешние проверки по-прежнему отдельное.
- Полный контракт находится в [`specs/DIRECTOR.md`](specs/DIRECTOR.md).

## Режиссёр — решения интервью 08.09.2026

### DEC-DIRECTOR-001 — workers, вход и расчёт группы

- Один active Director на channel; automatic failover отсутствует.
- Director управляет только явно выбранными enabled lurker accounts этого channel.
- Первый вход каждого lurker в stream-session независимо планируется случайно в диапазоне 0–30 минут.
- Reconnect уже входившего lurker начинается сразу по обычному backoff, без новой join-delay.
- «Зайти сейчас» доступно только для `scheduled`, отменяет timer и создаёт одну connect attempt.
- Lurker подключается молча. Если доступных workers ноль, moment фиксируется как skipped и позже не
  воспроизводится.
- Assignment mode по умолчанию — backend random среди enabled, online и свободных workers.
- Для любого размера группы owner может выбрать absolute или percentage mode.
- Absolute defaults: small 0–3, medium 4–12, large 13–30 bots.
- Percentage defaults: small 0–10%, medium 10–35%, large 35–70%.
- Процент >0 округляется до ближайшего целого с minimum 1; 0% означает молчание.
- Group percentages суммарно равны общему проценту; целые accounts распределяются методом наибольшего
  остатка.
- Plan использует immutable snapshot доступных workers и не пересчитывается после connect/disconnect.

### DEC-DIRECTOR-002 — анализ, health и stream lifecycle

- Fixed analysis interval default 15 seconds; high-priority wake cooldown default 5 seconds.
- Default send window 1–20 seconds; default TTL 45 seconds.
- Twitch offline grace default 60 seconds; новые plans блокируются сразу.
- Manual start отклоняется, если AI/Vision/speech не готовы; первый plan после 30 seconds warm context.
- Vision stale default 45 seconds; speech/transcriber heartbeat stale default 15 seconds.
- Тишина и статичный кадр считаются healthy, если source отправляет свежий успешный heartbeat/description.
- Speech Raid/End signal требует verified owner voice. Guest/unknown speech — контекст, но не команда.
- Incoming raid использует только точный Twitch event; ручная Raid-кнопка создаёт Director event, но
  не запускает Twitch raid.
- Manual Raid/End показывают preview и требуют подтверждения.
- Manual End закрывает только Director session, не Twitch stream и не остальные bots.
- Start/raid/end plans имеют высокий приоритет, но не отменяют уже запланированный обычный хвост.

### DEC-DIRECTOR-003 — AI compatibility и failures

- Director structured output использует JSON Schema/tool calling, если provider поддерживает; иначе
  strict JSON fallback.
- Model обязана пройти schema/hard-safety replay; несовместимая model не допускается в live.
- Полностью неразбираемый JSON получает одну repair attempt, затем moment skipped.
- Читаемый plan с невалидными частями не repair-ится: invalid parts отбрасываются, valid выполняются
  без компенсации.
- Consecutive AI error threshold настраивается 1–10, default 3; success сбрасывает счётчик.
- Automatic provider/model fallback отсутствует.
- После AI pause нужны 15 seconds healthy AI/Vision/speech и один valid dry-run без Twitch send;
  затем auto-resume без воспроизведения старых moments.
- Ollama image выбирается как последний официальный stable release и фиксируется exact digest после
  разрешённого health gate.

### DEC-DIRECTOR-004 — prompt, settings и modes

- Prompt versions хранятся все до ручного удаления с diff/replay metadata.
- Safety replay обязателен; качество новой версии оценивает и активирует owner.
- Во время live все Director settings read-only.
- Редактирование разрешено в `off` и `paused`; Save создаёт config version и использует dirty guard.
- Удаление старой prompt-version — обычная modal с dependencies; audit сохраняет metadata/hash.
- Suggest показывает весь plan, позволяет отредактировать и одной кнопкой отправить либо отклонить.
- Partial plan отображается жёлтым status с planned/valid/rejected и причинами.
- Template mode задаётся отдельно: `exact`, `placeholders` или `adaptable`.

### DEC-DIRECTOR-005 — Pause, Stop, restart и emergency

- Обычная Pause замораживает unsent хвост до его исходного TTL.
- Resume после обычной Pause: 15 seconds health без dry-run, если config не менялся; новая config требует
  validation/replay.
- Отдельный Stop с confirmation закрывает Director session без финальной реакции, отменяет хвост и
  не останавливает Twitch/bots.
- После process restart прежняя session восстанавливается только в paused; unsent хвост отменён;
  Resume ручной после health.
- Emergency Stop доступен во вкладке, постоянной шапке и owner-defined hotkey без default.
- Emergency Stop мгновенный, без confirmation; отменяет хвост и запрещает планы.
- Resume после Emergency Stop только вручную, затем health 15 seconds + valid dry-run.
- Панель предлагает откат к последней рабочей prompt-version, но не применяет его автоматически.

### DEC-DIRECTOR-008 — отдельная панель роли

- **Supersedes:** часть `DEC-DIRECTOR-005` о постоянной кнопке Emergency Stop в общей шапке.
- Emergency Stop находится только внутри вкладки Director; owner-defined hotkey без default сохраняется.
- У назначенного Director account нет обычной панели chat-bot settings: карточка ведёт только в
  отдельную Director-панель, где находятся channel scope, provider/model, workers и lifecycle.
- Переключатель «только смотрит» убран из быстрых действий карточек всех ботов; сама настройка
  остаётся в подробных настройках поведения.
- Настройки выбранной обычной роли показываются прямо рядом с выбором роли, а не прячутся в другой
  вкладке среди общих блоков.

### DEC-DIRECTOR-009 — replay, активация prompt и назначение Suggest

- **Supersedes:** часть `DEC-DIRECTOR-004` о кнопке отправки plan из Suggest.
- Проверка model/prompt выполняет настоящий безопасный schema/hard-safety replay через выбранный
  provider/model; automated tests используют изолированный fake-provider seam без сети.
- Активация prompt-version требует одновременно успешный replay для exact provider/model и явное
  подтверждение owner, что качество примеров проверено. Подтверждение привязано к `replay_run_id`;
  смена Director config или effective provider endpoint делает прежнее доказательство неактуальным.
- Suggest не управляет эфиром и никогда не отправляет сообщения в Twitch. Owner просматривает и при
  необходимости редактирует plan, затем сохраняет его как approved example либо отклоняет.
- Approved examples используются Director как контекст будущих решений; в live Director действует
  автономно и не ожидает owner approval во время стрима.

### DEC-BOTS-004 — видимость настроек по роли

- Общие технические настройки обычных ролей сохраняются, но поведенческие вкладки фильтруются по роли.
- Moderator показывает настройки модерации; характер/AI общения применяются, только когда разрешена
  chat activity. Voice companion показывает характер и AI/TTS. Lurker оставляет только channel scope и
  разрешение ответа на прямое `@`. Director использует только отдельную Director-панель.

### DEC-DIRECTOR-006 — storage, export и deletion

- Live frame storage default off; после включения retention 90 days или 10 GB per channel, что наступит
  раньше. Pinned frames имеют отдельный hard limit 5 GB без auto-delete.
- Approved training assets имеют отдельный hard limit 10 GB; при заполнении новые approvals блокируются.
- Full transcripts: warning status при 5 GB, hard recording limit 20 GB. После limit Director live
  продолжает использовать свежую речь без сохранения полной истории.
- Session export ZIP всегда содержит TXT+JSON transcript, audit и все frames, с настоящими usernames.
- Owner отказался от warning перед backup/export; это уточнено отдельным решением `DEC-BACKUP-002`.
- Session deletion показывает состав и требует ввести `УДАЛИТЬ`; общей «удалить всё» нет.
- Удаляются transcript, все live frames и raw rejected evidence session; audit остаётся без дословной
  речи/изображений.
- Approved example является отдельным asset и переживает удаление source session. Внутри example
  usernames заменяются стабильными `Viewer-1`, `Viewer-2` только в пределах этого example.
- Удаление approved example показывает размер/references и удаляет его отдельные assets; audit сохраняет
  metadata/hash.

### DEC-DIRECTOR-007 — copypasta, chants и messages

- Обычный generated text ограничен 120 symbols.
- Exact copypasta берётся только из одного Twitch message viewer или streamer; несколько сообщений не
  склеиваются. Отдельный channel toggle default off.
- Director может использовать любой настроенный reaction level для copypasta.
- Exact text не переписывается. Hard-filtered source автоматически не отправляется, идёт owner в suggest
  и может стать только negative training example.
- Hard filters всегда запрещают personal data/secrets, URL, commands, @mentions, system/mod/integration
  messages и попытки управлять integrations. Мат/caps/topics проходят channel outgoing policy.
- После использования copypasta может стать AI-added temporary session template и повторяться без нового
  viewer message; permanent только после owner approval.
- Каждый repeat создаёт новый plan и заново проходит context/availability/filters/TTL/Twitch result.
- Cooldown exact copypasta отсутствует, но technical plan/group/message idempotency сохраняется.
- AI-added chant действует до конца session; permanent chant требует owner approval.
- `diverse` similarity имеет channel setting `off/normal/strict`, default normal.
- Twitch reject/slow/rate/duplicate не обходится другим account или изменением текста: message skipped.
- Own bot messages видны Director как `own_bot`, но не считаются viewer activity/language/hype/copypasta
  source. При этом owner выбрал показывать и считать их как обычные сообщения в widgets/general analytics.
- Default language Auto + translit; реальные viewers и verified streamer определяют language, own bots — нет.
- Automation disclosure находится в Twitch profile каждого lurker и вручную контролируется владельцем;
  панель это не проверяет и не редактирует.

### DEC-OAUTH-001 — авто-обновление токенов и статусы в панели

- Фоновый авто-refresh (`token_refresh_loop`) включается **по умолчанию**.
- Продлеваются только аккаунты с непустым `refresh_token` и настроенным Helix
  client id/secret; это технический предел Twitch, обходить его не нужно.
- Панель показывает на карточке бота статус токена значками (без чисел и дат):
  живой / истекает / истёк / **не продлевается** (ручной токен без refresh_token) /
  неизвестно.
- Для ботов без refresh_token и без даты истечения честный статус «не продлевается»;
  панель не обещает авто-обновление там, где оно невозможно.
- Добавляется кнопка ручного «Обновить» для ботов с refresh_token (существующий
  endpoint `POST /api/accounts/{id}/refresh-token`).
- Числа «дней осталось» и точные даты в UI не показываются (для вставленных вручную
  токенов дата неизвестна).

### DEC-BULK-001 — массовые операции боты × каналы

- Оба направления: **выбранные боты → добавить им каналы** и **канал → добавить к нему
  выбранных ботов**.
- Канал вводится текстом или выбирается из уже используемых; новых сущностей
  «канал-первого-класса» с собственной страницей не создаётся.
- Каждая пара бот×канал обрабатывается отдельной попыткой; уже существующие связки
  не дублируются (idempotent INSERT OR IGNORE).
- Результат — **per-item отчёт**: успешно / пропущено (уже есть) / ошибка (причина).
  Частичный сбой не прерывает остальные элементы.

### DEC-BULK-002 — проверка работоспособности на тестовом канале

- После массовых операций доступна проверка выбранных ботов: пассивная часть —
  валидация токена, подключение к каналу (IRC online) и чтение чата.
- Дополнительно каждый проверенный бот отправляет **ровно одно короткое контрольное
  сообщение** вида «✅ проверка связи [ник]» — без пачек и пауз-хореографии.
- Тестовый канал **выбирается в момент запуска** проверки; ничего не хардкодится
  и не фиксируется в настройках как постоянный полигон.
- Контрольное сообщение — единственный случай, когда проверка пишет в реальный чат;
  сама операция добавления каналов сообщений не отправляет.

### DEC-LOG-001 — правдивый статус токена Chat Logger

- «Токен истёк» показывается **только** при подтверждённом 401 от Twitch validate.
- Сетевая ошибка/5xx/429 — отдельное состояние «не удалось проверить»
  (`expires_in_days: null`), не «истёк» и не 0 дней.
- Негативный результат не кэшируется на 10 минут; позитивный кэш допустим.
- Токен Chat Logger остаётся ручным и непродляемым: подсказка «вставь новый» сохраняется,
  авто-обновление и мониторинг не добавляются (owner отказался).

### DEC-OAUTH-002 — источник статуса токена

- Статусы токенов проверяются **по запросу** (открытие/обновление карточки или списка),
  без фонового опроса Twitch validate.
- Для ботов с `token_expires_at` статус считается из базы без внешних запросов.
- Для вставленных вручную токенов живость подтверждает только validate-запрос;
  результат кэшируется на короткое время (порядка 10 минут), лимиты Twitch не задеваются.

### DEC-BULK-003 — отправка контрольных сообщений

- Проверенные боты отправляют контрольные сообщения **по очереди** с коротким интервалом
  (~2–3 секунды), не пачкой — чтобы Twitch не отклонял их как дубликаты/спам.
- Если Twitch всё же отклонил отправку, результат показывается в per-item отчёте как ошибка
  с причиной (это валидный результат проверки).

### DEC-LURKER-002 — представление lurkers в списке ботов

- Lurkers группируются **постоянной сворачиваемой секцией «Lurkers» сверху** списка ботов;
  остальные боты — под ней.
- В секции всегда видно количество lurkers и их статусы; у lurker-карточек действуют
  упрощения из `DEC-LURKER-001`.

### DEC-OAUTH-003 — настраиваемый порог «истекает»

- Жёлтый значок «истекает» включается, когда до истечения осталось меньше порога.
- Порог настраивается в панели; значение по умолчанию — 7 дней.

### DEC-OAUTH-004 — неудачный авто-refresh

- Неудачное обновление (сеть, ошибка Twitch) не выключает бота и не шумит: попытка просто
  повторяется в следующем цикле (10 минут), бот продолжает работать на старом токене.
- Если токен реально истёк — красный статус с причиной; отдельный значок «ошибка обновления»
  не добавляется.

### DEC-OAUTH-005 — вставка токена без refresh_token

- При добавлении/редактировании бота с токеном без refresh_token показывается мягкое
  пояснение «этот токен не будет продлеваться автоматически».
- Добавление не блокируется и не требует подтверждения.

### DEC-BULK-004 — вкладка «Каналы»

- **Supersedes:** пункт `DEC-BULK-001` об отсутствии сущности «канал первого класса».
- В панели появляется отдельная вкладка «Каналы»: список используемых каналов.
- У каждого канала видно подробно: сколько ботов добавлено и кто из них реально подключён
  (runtime-статус подключения к этому каналу).
- Из вкладки «Каналы» запускается операция «к каналу добавить ботов» (`DEC-BULK-001`);
  направление «выбранным ботам добавить каналы» остаётся в bulk-bar списка ботов.

### DEC-BULK-005 — единый процесс «добавить и проверить»

- Массовое добавление и проверка — **один процесс**: после добавления каналов сразу
  запускается проверка из `DEC-BULK-002` (validate, IRC join, контрольные сообщения
  по очереди) без отдельного клика.
- Отдельная кнопка проверки для уже добавленных ботов тоже остаётся.
- Per-item отчёт массовой операции **скачивается** (файл CSV/текст) в дополнение к
  показу в панели; отчёт проверки объединяется с отчётом добавления.

### DEC-BOTS-003 — lurker без особого автостарта

- Lurkers подчиняются общей логике автостарта/входа в каналы, как остальные боты.
- Никакого расписания входа и отдельной логики подключения для lurker не делается.

### DEC-UI-003 — i18n новых поверхностей

- **Уточняет `DEC-UI-001`:** все строки новых фич (статусы токенов, секция «Lurkers»,
  вкладка «Каналы», отчёты массовых операций и проверки) сразу на RU/EN/UA;
  поэтапный «сначала русский» не используется.

### DEC-BULK-006 — формат и хранение отчётов

- Скачиваемый отчёт доступен в двух видах: **CSV** (бот, канал, результат, причина,
  статус проверки — для таблиц) и **читаемый текстовый лог** (построчный просмотр).
- Отчёты как сущность в базе не хранятся; в существующий audit log пишется только
  запись операции: кто запустил, направление, время, счётчики результатов — без
  построчных результатов.

### DEC-BULK-007 — критерий «бот реально читает чат»

- Пассивная проверка считает бота подтверждённым, когда: токен валиден, IRC-join
  прошёл (статус online) **и** бот получил хотя бы одно реальное сообщение из чата
  за окно ожидания (до ~30–60 секунд).
- Если в тестовом чате нет активности за это окно — честный результат
  «не подтверждено: сообщений не было», а не «успех».
- Бесконечное ожидание не используется; пользователь может остановить проверку.

### DEC-BULK-008 — редактируемое контрольное сообщение

- Текст контрольного сообщения можно вписать свой при запуске проверки.
- Значение по умолчанию — фиксированный шаблон «✅ проверка связи [ник]»;
  маркер [ник] заменяется на ник отправляющего бота.
