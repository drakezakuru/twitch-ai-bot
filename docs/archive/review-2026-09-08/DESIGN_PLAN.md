# План по дизайну виджетов и панели

> ⛔ **ВЫПОЛНЯТЬ ТОЛЬКО ПО ЯВНОЙ ПРОСЬБЕ ВЛАДЕЛЬЦА.**
> Это план, а не задание в работе. Ни один пункт не начинать без отдельного «поехали»
> по конкретному пункту. Причина такая же, как у Waves 5/6: правки дизайна меняют кадр
> в уже настроенных OBS-сценах, и регресс виден только глазами на живой сцене.
>
> Инварианты (как во всём проекте): публичные URL и параметры сохраняются, новые
> параметры — только **опциональные с прежним значением по умолчанию**, чтобы старый
> Browser Source выглядел ровно как раньше. Схему БД не ломать.
>
> Статусы: ⬜ не начато · 🔶 нужно решение владельца · ✅ готово.

## 1. Запрос владельца: настройки дизайна для `chat-reader` и `tts-raw`

### Что есть сейчас

| Виджет | Настраивается через URL | Захардкожено |
|---|---|---|
| `chat-reader` | `account_id`, `label`, `scale`, `api` | цвет акцента `#22d3ee`, фон `rgba(15,15,25,0.9)`, размер шрифта 20px, позиция (снизу по центру), время показа 8с, ширина 640px |
| `tts-raw` (`/obs/tts`) | `channel`, `min_role`, `lang`, `rate`, `volume`, `max_chars` | вообще всё оформление: фон `rgba(0,0,0,0.65..0.7)`, цвета статуса `#00ff7f`/`#ff5252`, размер 13px, позиции статуса и строки |

То есть у `tts-raw` **нет ни одного** параметра оформления, у `chat-reader` — только масштаб.

### ✅ 1.1 Общий набор параметров оформления (обоим виджетам)

Предлагаемые URL-параметры — единые по имени для всех виджетов, чтобы не запоминать
разные названия:

| Параметр | Значения | По умолчанию | Что делает |
|---|---|---|---|
| `theme` | `dark` \| `light` \| `neon` \| `fire` \| `glass` \| `mono` | `dark` | готовая схема (как уже сделано у `emoji-chat`) |
| `accent` | hex | текущий цвет виджета | цвет рамки/ника/акцентов |
| `bg` | hex | текущий | цвет подложки |
| `opacity` | `0`–`1` | текущая | прозрачность подложки, **не** текста — текст должен остаться читаемым |
| `radius` | `0`–`32` | текущий | закругление углов |
| `font` | `sans` \| `serif` \| `mono` \| `condensed` | `sans` | семейство шрифта |
| `size` | `12`–`48` | текущий | базовый кегль |
| `scale` | `0.5`–`3` | `1` | общий масштаб (у `chat-reader` уже есть) |
| `pos` | `bl` \| `bc` \| `br` \| `tl` \| `tc` \| `tr` | текущая | угол/край кадра |
| `shadow` | `0` \| `1` | `1` | тень и свечение (в OBS иногда мешает) |

Дополнительно только для `chat-reader`: `hold` (сколько секунд держать реплику,
сейчас жёстко 8000 мс) и `maxw` (максимальная ширина пузыря, сейчас 640px).
Только для `tts-raw`: `showstatus=0|1` — прятать техническую строку статуса,
которая в эфире не нужна.

**Контракт владельца 04.09:** оформление хранится глобально для каждого виджета,
не per-account/per-channel. Функциональные настройки `chat-reader` остаются
per-account, а параметры URL конкретного OBS Browser Source перекрывают глобальное
оформление. Диапазоны: `hold=1..60` секунд, `maxw=240..1600` px. Старые URL без
новых параметров сохраняют прежний кадр: opacity `0.9` у `chat-reader`; у `tts-raw`
основная строка `0.65`, статус `0.70`. Один ползунок `opacity` меняет обе подложки
`tts-raw`, сохраняя разницу `+0.05`. `pos` двигает только строку сообщения, статус
остаётся сверху слева и скрывается через `showstatus=0`.

**Как делать (важно):** значения подставляет **роут** в CSS-переменные
(`--accent`, `--bg`, `--opacity` и т.д.), как уже сделано у `tts-bot`
(`__TTS_ACCENT__`) и `emoji-chat` (`__THEME__`). Цвета — строго через
`_normalize_hex()` из `app/widgets.py`, тема и `pos`/`font` — через белый список.
Прямая подстановка значения из URL в разметку = HTML-инъекция; именно этот класс
бага уже находили у `emoji-chat`.

**Готово, когда:** оба виджета открываются без параметров и выглядят как сейчас
(это главный критерий — старые OBS-сцены не должны измениться), каждый параметр
меняет кадр, мусорное значение откатывается на дефолт, есть guard-тест на подстановку
и на отбой инъекции (по образцу `test_emoji_chat_theme_is_substituted_by_route`).

### ✅ 1.2 Где настраивать: URL или форма в панели

URL-параметры — минимум работы и сразу дают результат. Но подбирать цвет, дописывая
`?accent=%2322d3ee`, неудобно.

Варианты:
- **A. Только URL.** Дёшево, но настройка вручную.
- **B. URL + форма в карточке виджета** с color-picker и живым iframe-превью, как уже
  сделано для `goals`/`sub-goal`/`now-playing`. Настройки в БД, URL продолжает
  перекрывать их (как у `top-donator`).
- **C. Форма + пресеты** («Минимал», «Неон», «Стекло»), чтобы одним кликом.

**Решение владельца 04.09: вариант B** — URL + форма с color-picker и живым
iframe-превью в карточке виджета. Пресеты пока не входят в решение. Реализация
по-прежнему начинается только после отдельного «поехали» по §1.1–1.2.

**Выполнено 04.09:** оба роута принимают безопасно нормализованные параметры,
глобальное оформление хранится в существующей таблице `settings` без изменения
схемы, а старые URL и функциональные параметры сохранены. В панели добавлены формы
с color-picker, сохранением, копированием собранного URL и живым iframe-превью;
подписи локализованы RU/EN/UA. Дефолтные `chat-reader` и `tts-raw` подтверждены
pixel-identical снимками; отдельно сняты
кастомные верхние позиции, цвета, шрифты и скрытие TTS-статуса. Guard-тесты:
`tests/test_widget_design_settings.py` и `tests/test_widget_design_panel.py`.

## 2. Что ещё нашёл по дизайну виджетов

Аудит всех 31 виджета по трём параметрам (`theme` / `opacity` / `scale`):

### ✅ 2.1 Прозрачность подложек — готово 04.09

У всех 30 активных виджетов с подложкой есть опциональный URL-параметр
`opacity=0..1`; `mascot` исключён, потому что у него прозрачный canvas без
подложки. Значение ограничивается диапазоном, не вставляется в HTML и меняет
только CSS-фон — текст, границы и содержимое сохраняют исходную яркость.

Для 28 оставшихся виджетов используется общий безопасный runtime
`widgets/_shared/appearance.js` и CSS-переменная `--widget-opacity`; ранее
сделанные `chat-reader` и `tts-raw` сохраняют настройки из §1.1. Без параметра
все старые alpha-значения остаются fallback-значениями CSS, поэтому старые OBS URL
не меняют кадр. Guard: `tests/test_widget_opacity.py`. Визуальная проверка:
`scripts/qa_shoot.py qa-opacity` — 11/11 кадров, включая обычную и градиентную
подложки с default и `opacity=.2`.

### ✅ 2.1a Рекомендуемый размер Browser Source — готово 04.09

Для всех 31 активных контрактов в едином inventory зафиксированы рекомендуемые
ширина и высота OBS Browser Source. Панель показывает размер в каждой карточке и
подставляет его в инструкцию вместо прежнего общего совета `800×600`.
Контентные карточки получили компактные холсты, `follower-ticker` — широкую полосу,
а полноэкранные эффекты `animated-bg`, `anime-runner`, `blur-guard-v2` и
`media-share` сохранили `1920×1080`. Публичные URL и вёрстка самих виджетов не
менялись. Guard: `tests/test_w7_preview_contracts.py` и
`tests/test_p5_widget_instructions.py`.

### ✅ 2.2 Общие темы — закрыто 04.09

Все 31 активных контракта принимают общий whitelist
`dark/light/neon/fire/glass/mono`. 29 шаблонов используют opt-in semantic tokens;
`chat-reader` и `tts-raw` сохраняют собственный native design parser с тем же набором
палитр, чтобы shared CSS не перебивал сохранённые `accent`/`bg`.

**Первая группа готова:** `countdown`, `donation-challenge`, `latest-event-card`
и `top-donator` используют общие семантические токены для
`dark/light/neon/fire/glass/mono`. Старые URL, внешний вид без параметров и
специальные темы `minimal`/`rainbow` сохранены. Guard:
`tests/test_widget_theme_cohort_cards.py`.

**Вторая группа готова:** компактные metric-карточки `emoji-leaderboard`,
`hype-meter` и `subathon-timer` подключены к тем же surface/accent/text/muted/fill
токенам. Без `theme` их кадры побайтно совпадают с baseline; `limit`, `scale`,
`window`, `threshold`, состояния таймера и live-данные не менялись. Guard:
`tests/test_widget_theme_cohort_metrics.py`.

**Третья группа готова:** `recent-events` и `soundboard` используют общие surface
и accent tokens. У Soundboard semantic-класс сохраняется при каждом обновлении
WS-состояния; статусные зелёная/жёлтая точки и audio/reconnect-контракт не менялись.
Оба default-кадра побайтно совпадают с baseline. Guard:
`tests/test_widget_theme_cohort_stream.py`.

**Остальные группы готовы:** существующие тематические оверлеи (`goals`,
`now-playing`, `schedule`, `follower-ticker`, `stream-session`, `emoji-chat`),
content-виджеты (`lower-third`, `chat-highlight`, `song-request`) и live-виджеты
(`chat-roulette`, `clip-moments`, `tts-bot`, `tts-chat-overlay`, `mod-feed`,
`sub-goal`, `media-share`) подключены к тем же токенам. Persisted и legacy-темы
`glow`, `purple`, `minimal`, `rainbow`, `rec`, `retro`, `arcade`, `cyber`,
`corporate`, а также сцены `tree/reef/city` сохранены.

Для полноэкранных контрактов тема действует только на безопасный UI: banner у
`animated-bg`, speech bubble у `anime-runner`, HUD у `blur-guard-v2`; canvas,
video, blur-region и авторский арт не перекрашиваются. У `mascot` тема влияет лишь
на служебную sleep-индикацию, не на SVG/изображение персонажа. `mod-feed` переведён
на общий loader, поэтому его реальный OBS-route теперь получает versioned shared
CSS/runtime. Guards: `tests/test_widget_theme_cohort_core.py`,
`tests/test_widget_theme_cohort_content.py`, `tests/test_widget_theme_cohort_live.py`,
`tests/test_widget_theme_coverage.py`.

### ✅ 2.3 Набор тем у разных виджетов разный — закрыто 04.09

У `emoji-chat` — `dark/light/neon/fire/glass`, у других — свои наборы. Один и тот же
`?theme=neon` в разных виджетах даёт несогласованные цвета, и сцена выглядит
собранной из кусков.

**Что сделать:** вынести палитры в `widgets/_shared/theme.css` (файл уже есть и
почти не используется) и подключать оттуда — тем же приёмом, которым Waves 5/6
вынесли общий рантайм. Тогда «неон» везде один и тот же.

**Сделано:** общие безопасные палитры `dark/light/neon/fire/glass/mono` и их
семантические токены вынесены в `widgets/_shared/theme.css`. Общий runtime
принимает только эти имена и подключается вместе с CSS во все 31 виджет;
неизвестные и legacy-темы не переопределяются. Фундамент визуально инертен до
миграции конкретного шаблона. Shared assets получают версию по `mtime`, изменение
CSS/JS инвалидирует HTML-кэш, а service worker использует `widget-cache-v2` и
network-first для `/widget/_shared/*`. Роут отдаёт CSS как `text/css`, JS как
`application/javascript`, поэтому Browser Source не игнорирует stylesheet.
Миграция §2.2 завершена для всех 31 активных контрактов с сохранением текущих
defaults и собственных тем (`rec`, `rainbow`, `arcade`, `corporate` и другие).
Полное покрытие и исключения для native/fullscreen контрактов зафиксированы в
`tests/test_widget_theme_coverage.py`.

### ✅ 2.4 Безопасный масштаб bounded overlays — готово 04.09

Общий runtime принимает числовой `scale`, ограничивает его диапазоном `0.5..3`
и применяет к 24 bounded overlays без растягивания Browser Source. Старые
реализации `emoji-chat`, `emoji-leaderboard`, `hype-meter` и `subathon-timer`
переведены на тот же parser. Fullscreen-контракты, strip и native design parser
не перехватываются; существующий специальный `scale` у `media-share` сохранён.

### ✅ 2.5 Whitelist-позиция bounded overlays — готово 04.09

Те же 24 bounded overlays принимают только `pos=tl|tc|tr|bl|bc|br`. Общий adapter
позиционирует внешний visual root, не перезаписывая локальные `transform`-анимации;
без параметра DOM/layout не меняются. Исключены fullscreen `animated-bg`,
`anime-runner`, `blur-guard-v2`, `media-share` и strip `follower-ticker`.
`chat-reader`, `tts-raw` сохраняют native parser, а `anime-runner` — собственные
`corner/path`. Guard: `tests/test_widget_scale_position.py`; все 24 custom-кадра
проверены, matching default-кадры Goals/Chat Reader совпали с baseline по SHA-256.

## 3. Панель: что можно сказать и чего нельзя

### ✅ 3.0 Блокирующее зависание исправлено 04.09; механизм удалён 05.09

Причиной зависания был `MutationObserver` прежнего режима приватности. После нового
owner-решения глобальный toggle, observer и динамическая маскировка удалены полностью;
секреты теперь защищаются постоянными password-полями и redacted API contracts.
Anti-regression guard: `tests/test_w10_privacy_mode.py`.

Пункты ниже остаются **гипотезами из чтения кода и вёрстки**, а не итогами полного
визуального ревью. Без подтверждения глазами их реализовывать не стоит.

### ⬜ 3.1 Ширина панели не ограничена

В `static/app.css` у контейнера нет `max-width`: на мониторе 2560px строки таблиц и
формы растягиваются на всю ширину, читать тяжело. Обычное решение — `max-width`
порядка 1400–1600px с центрированием, при этом широкие таблицы могут оставаться
на полную ширину.

### ⬜ 3.2 Панель — одна страница с 17 скриптами (303 КБ HTML)

Всё грузится сразу, включая вкладки, которые пользователь может не открыть.
Это увеличивает стартовую стоимость, но причиной зависания из §3.0 не было. Ленивую
загрузку по вкладкам можно рассмотреть отдельно — это уже архитектура, не дизайн.

### 🔶 3.3 Единая палитра для панели и виджетов

Если делать §2.3 (общие темы виджетов), логично взять те же переменные и в панель,
чтобы «неон» в панели и в кадре совпадал. Нужно решение, надо ли это вообще.
