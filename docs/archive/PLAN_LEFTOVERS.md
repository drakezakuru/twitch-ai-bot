## Чат-логгер (старт «логгер поехали» + аккаунт) — ✅ v1 сделано 02.09 (`6d103fb`)

**Зачем**: кнопка C1 «Собрать стиль чатера» нуждается в истории чатеров на
чужих каналах. Внешних источников НЕТ (SE /kappa — 404; ivr.fi — пусто на
наших каналах). Единственный путь — свой логгер, сидящий в чужих чатах.

**Как работает** (простыми словами):
- Логгер — отдельная программа (НЕ панель, НЕ бот-болтун).
- Заходит в Twitch-чат как зритель (IRC, OAuth chat:read) и ЧИТАЕТ.
- Одно соединение → ~100 каналов одновременно. Стримерам не видно, не мешает.
- Каждое сообщение → (канал, ник, текст, время) в SQLite + дневной файл
  `logs/<стример>/2026-09-02.log`.
- Один аккаунт → столько стримеров, сколько нужно. Токен ~60 дней,
  refresh автоматом.
- Только публичные чаты (саб-моды — нет).

**Хостинг** (гибко):
- Старт: Steam Deck рядом с панелью (ноль расходов, минус: дыры при выкл. Deck).
- Потом: VPS $3-5/мес или бесплатный tier (Oracle Free / Fly.io / Railway).
- Запуск: docker-compose из репо, панель не нужна.

**Аккаунт**: владелец добавляет САМ из панели (вкладка «📡 Чат-логгер»):

## Если у владельца что-то не работает (мини-траблшутинг)

1. **Панель выглядит сломанной / нет JS** — рестарт `python3 run.py` + Ctrl+Shift+R
   (кэш статики). Проверка: консоль браузера (F12) — красные ошибки скопировать сюда.
2. **«Ошибка загрузки: Method Not Allowed» на вкладке бота** — известный баг A1
   (вкладка «Общие», поля пустые) — чинится первым в A-блоке.
3. **Вечное «Загрузка...»** в Аналитике — A2 (до фикса: данные реально пусты
   на свежей базе — это не баг после рестарта).
4. **TTS/оверлеи в OBS** — проверять на копии виджет-URL из карточки; blur-guard
   карточка ведёт на v2.
5. **Логи**: `logs/panel.log` (панель), «📋 Последние логи» в Настройках — хвост.
6. **БД**: `data/bot.db` живой — тесты его не трогают (tmp_db); бэкапы см. «💾 Резервная копия».
