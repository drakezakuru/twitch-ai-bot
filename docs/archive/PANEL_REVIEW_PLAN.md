## Границы и приоритеты

**НЕ аудируем** (вне сессии): рантайм ботов и Twitch API (живая проверка — владелец),
поведение виджетов внутри OBS (только через владельца), безопасность auth
(отдельное решение владельца; в отчёт — одна строка «auth=False, осознанно»).

**Severity находок**: `стрим-блокер` (ломается во время эфира: виджеты, WS, TTS, биндинги) →
`баг` → `UX` → `косметика`. Порядок фиксов в Ф4 = по severity, внутри — по дате.
**Исключение из правила «ничего не чинить до Ф4»**: стрим-блокеры чинятся СРАЗУ,
одним коммитом с тестом, с пометкой в отчёте.

**DoD строки отчёта**: заполнены все 5 колонок + вердикт владельца
(ок / баг # / перенести / непонятно — вопрос). Строка без вердикта = не готова.

## Почему «так, а не иначе» — принцип (зафиксировать в отчёте для каждой карточки)

Место карточки определяется цепочкой: **где данные → там эндпоинт → там карточка**.
В отчёте для каждой карточки 5 колонок:

| колонка | источник ответа |
|---|---|
| что делает + почему здесь | код: чанк `static/app/NN_*.js` + роут-модуль `app/routes_*.py` + таблица в `database.py` |
| альтернатива (куда логичнее) | эвристики: per-bot данные → карточка бота; глобальные → раздел; настройки → Настройки |
| цена переноса S/M/L | S = карточка+эндпоинт в одном чанке/модуле; M = цепляется общее состояние/WS; L = общий файл (base.html, routes.py-ядро, ws) |
| рекомендация | оставить / перенести / переименовать / скрыть (+«не стоит: цена > польза») |
| баги | находки Ф1/Ф2 |

После P5-сплитов перенос стал ДЕШЕВЛЕ, чем был: карточка = правка своего
чанка `NN_*.js` (не монолита), эндпоинт = уже в своём `routes_*.py`.
Дорогие переносы (L) — те, что трогают `base.html`, ядро `routes.py`
(страницы/аккаунты), WS-протокол или общее состояние вкладок.
