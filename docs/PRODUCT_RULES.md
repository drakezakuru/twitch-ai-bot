## 1. Что это за проект

**Twitch AI Bot Panel** — веб-панель (FastAPI + SQLite + vanilla JS, порт 8000), которая:

1. **Боты в Twitch-чате** — AI-боты (со своим характером, памятью, ролью) сидят
   в чатах каналов, реагируют на сообщения/события, пишут от своего имени.
2. **TTS** — боты могут говорить голосом (пресеты или клоны), зрители могут
   заказывать озвучку за баллы канала.
3. **OBS-виджеты** — HTML-виджеты для стрима (цели, счётчики, таймеры, оверлеи),
   подключаются в OBS как browser-source по URL.
4. **Биндинги** — каждое действие виджета можно повесить на кнопку/команду/награду.
5. **Режим разговора** — владелец болтает с ботом прямо в панели (текст), бот
   отвечает с тем же характером/памятью и может озвучивать ответы.
6. **Модерация, аналитика, чат-логгер** — вспомогательные подсистемы.

Стек: Python/FastAPI, SQLite (data/bot.db), vanilla JS (static/app/*.js),
шаблоны Jinja2 (templates/), WebSocket для живых обновлений.

## 2. ЖЁСТКИЕ ПРАВИЛА (нарушение = баг)

### Виджеты (OBS)
- **R-ВИД1: У каждого виджета ОБЯЗАНО быть живое превью** (iframe `.widget-preview`)
  в панели рядом с его формой. Нет превью — фича не считается готовой.
- **R-ВИД2: Превью не бывает белым/пустым.** Фон превью — тёмный
  (`#0f0f1a`/var(--bg-secondary)), в самом виджете прописан dark color-scheme.
- **R-ВИД3: Кнопки ручного управления (старт/сброс/+1) НЕ дублируются**
  на каждой карточке. Отдельной секции «Ручное управление» в панели больше нет
  (удалена решением владельца, Q06, 13.09.2026); ручное управление виджетами во
  время эфира — через биндинги и чат-команды.
- **R-ВИД4: У виджета не бывает «мёртвых» контролов.** Каждая кнопка в панели
  реально меняет виджет; ползунок меняет результат вживую (WS-обновление).

### Биндинги
- **R-БИН1: Биндинги — смысловые и уникальные под виджет.** Виджет процентов →
  действия «+1% / −1% / сброс»; счётчик смертей → «+1 смерть / −1 / сброс»;
  countdown → «старт / пауза / +5 мин». Универсальный «increment» без смысла — запрещён.
- **R-БИН2: Невозможно создать бинд с действием, которое не имеет смысла
  для этого виджета** (бэк валидирует по белому списку).

### UI панели (общие)
- **R-UI1: Ноль хардкод-строк в шаблонах/JS-рендерах** — всё через i18n
  (ru/en/ua, три словаря). Новая строка без ключа в 3 языках = баг.
- **R-UI2: У каждой настройки есть понятный лейбл и подпись-подсказка** («что это
  даёт»). Селект «выбрать бота» там, где логичнее свободный ввод, — подозрение на
  баг, обсуждать с владельцем.
- **R-UI3: Тёмная тема — единственная.** Новые элементы не должны ломать её
  (проверять превью/модалки на тёмном фоне).
- **R-UI4: Секреты защищаются всегда.** Глобального streamer/privacy toggle нет:
  ключи и токены вводятся через `type=password`, API не возвращает их значения,
  а безопасные статусы используют только маски. OBS Blur Guard — отдельная защита сцены.

### Роли ботов
- **R-РОЛЬ1: Роль меняет ПОВЕДЕНИЕ, а не отрезает каналы связи.** «Собеседник»
  пишет в чат, если владельцу так надо; ограничения роли — через настройки
  (частота/где пишет), а не через «никогда не пишет».
- **R-РОЛЬ2: Описание роли в UI = правда.** Текст карточки роли обязан совпадать
  с фактическим поведением (проверять на живом боте).

### Профили и данные
- **R-ДАН1: Каждый стример уникален.** Профили стримеров — per-channel по
  умолчанию; «глобальные» настройки допустимы только там, где владелец явно
  подтвердил это в `docs/DECISIONS.md`.
- **R-ДАН2: Миграции БД — только через `_add_column_if_missing`/аналогичные
  функции** (app/database.py), никаких ручных ALTER на живой базе.

### Провайдеры и AI
- **R-AI1: У кастом-провайдера могут быть отдельные chat- и vision-модели.**
  Vision-задачи берут модель из vision_models, а не первую chat-модель.
- **R-AI2: Пустой API-ключ при сохранении = «оставить старый»** (не затирать).
- **R-AI3: Fallback-цепочка провайдеров обязана логировать причину** каждого
  перехода (видно в think_error).

### Процесс
- **R-ПР1: После каждого завершённого шага — pytest + коммит в текущую ветку.**
  (Формулировка «в свою ветку» устарела: `DEC-OWNER-001` от 12.09.2026 отменил параллельные
  сессии и ветки `session/*` — работа идёт в `main` этой папки.)
- **R-ПР2: Общие файлы — только точечные Edit, не полное переписывание.**
- **R-ПР3: Не удалять runtime/API/data без явного решения в `docs/DECISIONS.md` и пункта
  в единственном `PLAN_TODO.md`.**
- **R-ПР4: Browser/OBS/device acceptance не подменяется static-тестом**, но запускается только
  после явного разрешения владельца; до него статус остаётся pending.
- **R-ПР5: Перед новой работой перечитать `PLAN_TODO.md`, этот файл, `docs/DECISIONS.md` и
  релевантный раздел `docs/ARCHITECTURE.md`/`docs/specs/`.**

## 4. Правило вопросов

**Агент ОБЯЗАН задавать вопросы владельцу напрямую**, когда:
- требование можно понять двумя способами;
- фича противоречит правилам этого файла;

`docs/DECISIONS.md`; нерешённый вопрос остаётся только в `PLAN_TODO.md`.
